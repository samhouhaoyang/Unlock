# Unlock project plan

## Selected product and authority

Unlock addresses “If AI does the beginner work, where does expertise come from?” with an apprenticeship workflow for junior software engineers in VS Code. [product.md](product.md) is the authoritative v2.0 scope; [product.en.md](product.en.md) mirrors it. This replaces the accountant scenario and the ancestor FirstVisit candidate. Airwallex is a benchmark for a capable engineering organisation, not a required customer system or integration.

The app is not implemented. The old finance issues, PRs, fixture validators, and React plan do not count as SWE delivery.

## P0 delivery target

Build one integrated workflow from the VS Code command through authored task routing, a synthetic webhook-retry practice case, first prediction, hint exposure, deterministic test, wrong/correct preset patch review, separate sub-skill assessment, three evidence gates, and a persisted support-level update. The four-quadrant router preserves the distinction between real delivery and synthetic high-risk practice. The delayed G3 gate stays pending until a real eligible attempt at least 72 hours after a linked teaching attempt; do not pre-seed a pass for presentation.

The full stack and acceptance criteria are in product sections 7–8. No backend, model, company repository access, autonomous delivery, real mentor service, or VSIX publication belongs to P0. A reviewed static teaching card is enough for post-submission feedback. A live approval workflow is later scope.
