# Bound editor context to reviewed mentor lessons

Accepted for junior SWE product v2.1. `Unlock: Help me with this code` reads only a learner-selected, previewed, bounded range from the active VS Code editor. It may include file/language label and existing nearby diagnostics. It does not silently index other files, upload code, store raw code in learning history, execute workspace commands, or infer delivery safety from the excerpt. Missing or unsupported context produces a visible fallback.

A mentor can hand over a versioned local `*.unlock.json` lesson through the team's existing controlled review channel. The file declares its source, reviewer, target sub-skills, risk and learning rationale, optional snippet/reference diff, test prompt, answer key, applicability, and L1–L4 hints. The extension validates the format and displays snippets as read-only comparisons; it cannot authenticate the reviewer or automatically apply the code. No match means an unscored question or learner-previewed help request, not invented code-specific guidance.

Real editor context is local and unscored in P0. Only reviewed synthetic cases can pass G1–G3 and change default help. A later opt-in LLM may draft a contextual question or rephrase approved hints, but cannot determine risk, answer truth, gate evidence, or support transitions. Any pre-submission model hint is help exposure. This preserves the distinction between useful in-workflow support and auditable evidence of independent learning.
