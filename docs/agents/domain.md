# Domain docs

Use a single context for this repository: `CONTEXT.md` at the root and system decisions in `docs/adr/`.

Before exploring code, read the root `CONTEXT.md` and any relevant ADRs in `docs/adr/`. If they do not exist yet, continue silently. Domain-modeling skills can create them when terms or decisions are established.

Use the glossary’s terms in issues, proposals, hypotheses, and tests. If a needed term is missing, reconsider the wording or note the gap for domain modeling. Flag any conflict with an existing ADR explicitly.
