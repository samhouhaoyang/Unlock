# Evidence memo: junior software engineers, with Airwallex as a benchmark

Researched 30 September 2026. This primary-source note supports the accepted junior SWE product direction; it is not evidence from interviews with Airwallex staff. Public job descriptions and product documentation show plausible work; the proposed journey below is a **hypothesis to test**, not a claim about a particular internal team or repository.

## What the sources establish

1. **The learner is an AI-using engineer, not an AI-avoiding student.** Airwallex's software engineering intern description expects fundamentals, ownership of a scoped project, a mentor/manager, and thoughtful use of LLM tools for research, prototyping, debugging, testing, and documentation. It names Kotlin, Kafka, Kubernetes, and React, and says interviewers may assess problem solving with/without AI and the ability to evaluate or challenge AI suggestions. [Airwallex Software Engineer Intern, Summer 2027](https://careers.airwallex.com/job/6cdb0f39-234a-4234-b1f1-cb48a1fa2795/software-engineer-intern-summer-2027/).
2. **A specific team's public onboarding path includes real engineering work.** An Airwallex Cards/Issuing intern description names buddy/mentor walkthroughs and weekly check-ins, standups, sprint reviews, cross-functional conversations, code reviews, testing, documentation, deployment, and a project showcase. This is evidence about that advertised placement, not a universal Airwallex process. [Airwallex Software Engineer Intern, Jan–Jun 2027](https://careers.airwallex.com/job/39651124-122a-4033-91a2-af2687b83441/software-engineer-intern-jan-to-jun-2027/).
3. **Airwallex already uses AI within its engineering workflow.** An Airwallex engineer describes AirCheck, an LLM reviewer for typos, bugs, and unclear merge-request descriptions, rolled out to engineers; the same account describes an IDE-integrated LLM assistant and AI chat. Unlock's unique role should be developing and showing the *junior's own judgment*, rather than claiming to be the team's first AI reviewer. The rollout/feedback statements are the engineer's account, not independently measured results. [Airwallex engineering interview](https://careers.airwallex.com/blog/airwallex-award-winning-innovation/).
4. **The domain supplies consequential decisions suitable for realistic practice.** Airwallex's public webhook documentation states that failed deliveries retry, duplicate events can arrive, event order is not guaranteed, and signatures must be verified before processing. Its Payments guide says idempotency keys prevent duplicate PaymentIntents on retries and payment fulfillment should follow success webhooks for asynchronous outcomes. These are *public integration rules*, not evidence about Airwallex's private production code. [Webhooks overview](https://www.airwallex.com/docs/developer-tools/webhooks/webhooks-overview); [PaymentIntents guide](https://www.airwallex.com/docs/payments/get-started/using-payments-intent-api).
5. **AI can improve immediate output while weakening new-skill acquisition in some settings.** In an Anthropic randomized experiment with 52 mostly junior Python engineers learning an unfamiliar asynchronous library, the AI-assisted group averaged 50% versus 67% on an immediate mastery quiz; the small completion-time advantage was not statistically significant. The largest gap was in debugging. A qualitative analysis associated conceptual inquiry and independent error resolution with better mastery than full code/debugging delegation. The study covers one short task and quiz, so it cannot establish long-term effects or Airwallex-specific outcomes. [Study report](https://www.anthropic.com/research/AI-assistance-coding-skills); [paper](https://arxiv.org/abs/2601.20245).
6. **The evidence is mixed, so the claim should be narrow.** A separate controlled experiment with 69 novice students aged 10–17 found AI assistance raised code-authoring performance without a statistically significant reduction in later post-test performance; this is not a workplace junior-SWE sample. A 2025 field analysis across three companies and 4,867 developers found more tasks completed with AI, especially among less experienced developers, but it measured productivity rather than learning. The product hypothesis is therefore that *a particular pattern of delegation can conceal skill gaps*, not that AI inevitably prevents expertise. [Novice programming experiment](https://arxiv.org/abs/2302.07427); [developer field experiments](https://www.microsoft.com/en-us/research/publication/the-effects-of-generative-ai-on-high-skilled-work-evidence-from-three-field-experiments-with-software-developers/).
7. **Authentic review feedback is a plausible teaching surface.** A Google case study examined 9 million reviewed changes plus interviews and survey responses; Google frames review as a way to spread coding knowledge. This supports locating mentor explanations near a code change, while the educational impact of Unlock's proposed experience-card format still needs testing. [Google modern code review study](https://research.google/pubs/modern-code-review-a-case-study-at-google/). Research on retrieval practice supports delayed checks over repeated study, but does not validate an exact 72-hour gate or numeric skill score for engineers. [Original retrieval experiment](https://doi.org/10.1126/science.1152408).

## Public-grounded workflow hypothesis to validate with engineers

**Persona:** a first-year backend or full-stack engineer on a payments-related project, using VS Code and an approved AI coding assistant. The team and editor choice are assumptions for the proposed demo; the Airwallex job pages establish the intern role, common engineering practices, and example stack, not a mandatory VS Code setup.

1. **Receive a scoped ticket and inspect code/tests.** The learner needs to identify the payment invariant and unknowns before asking AI to implement. Evidence: Airwallex advertises scoped project ownership and a mentor; public docs describe payment/webhook invariants. [Intern role](https://careers.airwallex.com/job/6cdb0f39-234a-4234-b1f1-cb48a1fa2795/software-engineer-intern-summer-2027/); [webhooks](https://www.airwallex.com/docs/developer-tools/webhooks/webhooks-overview).
2. **Make a 30–60-second pre-commitment in the editor:** “What could fail if events retry or arrive out of order?” Select a predicted failure mode and a test to run, with optional confidence. This is a design hypothesis motivated by the need to exercise reading/debugging before AI supplies the answer; the 30–60-second target needs usability testing. [AI skill experiment](https://www.anthropic.com/research/AI-assistance-coding-skills).
3. **Use AI freely for implementation and explanation.** A generated handler that processes each event twice or trusts delivery order is a labelled synthetic practice example. The learner checks it against tests/logs and the invariant, then accepts, fixes, or escalates with a reason. This fits Airwallex's stated expectation to evaluate AI suggestions and the public webhook specification. [Intern role](https://careers.airwallex.com/job/6cdb0f39-234a-4234-b1f1-cb48a1fa2795/software-engineer-intern-summer-2027/); [webhooks](https://www.airwallex.com/docs/developer-tools/webhooks/webhooks-overview).
4. **Prepare a merge request with a concise risk/test explanation.** The mentor reviews the human's reasoning, corrects one generalizable principle, and chooses whether to publish a de-identified learning note. The merge request, team review, and check-in setting are supported by Airwallex's descriptions; the note workflow is a proposed product feature. [Cards/Issuing placement](https://careers.airwallex.com/job/39651124-122a-4033-91a2-af2687b83441/software-engineer-intern-jan-to-jun-2027/); [AirCheck account](https://careers.airwallex.com/blog/airwallex-award-winning-innovation/).
5. **Later, test transfer on a fresh synthetic variant.** For example, the initial practice identifies duplicate event handling; a later independent case changes the relevant fact to an invalid signature or delayed success event. Record whether the junior selects the right test and explains the consequence before feedback. This tests a narrower construct than “is ready for production.” [Webhooks](https://www.airwallex.com/docs/developer-tools/webhooks/webhooks-overview); [retrieval study](https://doi.org/10.1126/science.1152408).

## VS Code extension feasibility and design constraints

- A command, contextual menu, Quick Pick, or short view can start the judgment prompt without replacing the editor. VS Code documents commands, views, and Quick Picks as standard extension surfaces. A webview can support a rich case interface, but VS Code advises sparing use because webviews are resource-heavy and may feel out of place. [UX overview](https://code.visualstudio.com/api/ux-guidelines/overview); [Webviews](https://code.visualstudio.com/api/ux-guidelines/webviews); [Webview API](https://code.visualstudio.com/api/extension-guides/webview).
- Avoid automatically opening exercises during editing or repeated popups. VS Code's notification guidance says to respect attention, limit notifications, and reserve modals for immediate user input. The best trigger is probably an explicit command or a brief, contextual prompt around a change/test/review; whether a specific trigger works needs a user test. [Notifications](https://code.visualstudio.com/api/ux-guidelines/notifications).
- The extension can store small local learning state in `workspaceState` or larger workspace-specific data in `storageUri`. `SecretStorage` is available for sensitive secrets, but P0 has no live credentials, private repositories, or automatic uploads. Respect Workspace Trust if executing tests or reading workspace-controlled configurations, and the user's telemetry setting if later measuring adoption. [Storage options](https://code.visualstudio.com/api/extension-capabilities/common-capabilities); [Workspace Trust](https://code.visualstudio.com/api/extension-guides/workspace-trust); [Telemetry guide](https://code.visualstudio.com/api/extension-guides/telemetry).
- VS Code exposes a Testing API, but it does not make arbitrary project tests automatically available; the extension would need an existing provider or an explicitly configured test command. For P0, deterministic fixture tests provide a testable boundary without promising plug-and-play test orchestration. [Testing API](https://code.visualstudio.com/api/extension-guides/testing).

## Unknowns that require discovery rather than assertion

- Whether the target Airwallex engineers use VS Code, which AI assistant is approved, and which source-control host, test runner, code-review system, and telemetry policies apply.
- Which newcomer tasks are genuinely low-risk enough for a pre-AI attempt, how much time mentors can spare, and what private code/data could be shown in an extension.
- Whether AirCheck's current comments already include teaching explanations and whether a separate learning extension would duplicate an internal workflow.
- Whether the proposed brief prediction, mentor note, and delayed synthetic check improve later independent review of *incorrect* AI output. Measure this in a pilot rather than claiming success from a short scripted session.

## Product implication

The defensible wedge is **“help a junior engineer verify and explain AI-generated changes against one payment invariant while doing their existing task”**. Keep the prior design's pre-AI judgment, graduated help, fresh transfer check, and reviewed mentor knowledge; replace the accountant's expense-allocation cards, amount grading, and generic task-routing page with code/test artifacts, a concrete risk decision, and a reviewer-ready explanation. The accepted product specification defines the actual P0 scope and gate rules; this memo remains supporting research, not product authority.
