# Research: contextual VS Code help and mentor snippets

30 September 2026. Scope: primary documentation and original research relevant to extending Unlock from authored practice cases to help grounded in the junior's current editor. This note distinguishes verified capabilities and findings from product recommendations; [product v2.1](../product.en.md) and the [shared contract](contracts.md) own the accepted P0 behaviour.

## Verified capabilities and constraints

- A desktop extension can inspect `window.activeTextEditor`, its `document`, `selection`, and `visibleRanges`; `TextDocument.getText(range)` can limit a read to the selected range. VS Code exposes editor/document change events and `languages.getDiagnostics(uri)`. Diagnostics are signals supplied by language tooling, not proof that a learner understands the code. [VS Code API reference](https://code.visualstudio.com/api/references/vscode-api).
- The extension can open text documents, including untitled documents with supplied content, and show them in an editor. The built-in `vscode.diff` command displays two resources side by side. These provide a native way to show a reviewed mentor snippet or compare an attempt with a reference without a custom code renderer. [VS Code API reference](https://code.visualstudio.com/api/references/vscode-api), [built-in commands](https://code.visualstudio.com/api/references/commands).
- VS Code's Testing API can discover tests and publish results. It does not make an arbitrary repository's tests available automatically; the extension must implement a controller or integrate an existing provider. [Testing API guide](https://code.visualstudio.com/api/extension-guides/testing). Hence the current P0 deterministic fixture and recorded observation remain an honest boundary.
- Workspace Trust offers Restricted Mode and `workspace.isTrusted`; an extension with limited support must gate execution-sensitive paths, and hiding a command alone is insufficient because commands can still be invoked. [Workspace Trust extension guide](https://code.visualstudio.com/api/extension-guides/workspace-trust). A webview should have minimal capabilities, restrictive `localResourceRoots`, a Content Security Policy, and sanitization of file contents, paths and settings rendered as HTML. [Webview security guidance](https://code.visualstudio.com/api/extension-guides/webview#security).
- If a future version uses an API key, VS Code documents `SecretStorage` for encrypted secret persistence; it should not be placed in workspace settings, case JSON, or learner snapshots. [VS Code remote extension guidance](https://code.visualstudio.com/api/advanced-topics/remote-extensions), [API reference](https://code.visualstudio.com/api/references/vscode-api).
- OpenAI's Structured Outputs can enforce a supported JSON schema but explicitly does **not** guarantee factual correctness. The provider recommends human oversight, especially for generated code, and testing for prompt injection. Code and comments read from an editor must therefore be treated as untrusted input if sent to a model. [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs), [safety best practices](https://developers.openai.com/api/docs/guides/safety-best-practices). An external API call also has data-handling consequences: OpenAI documents default abuse-monitoring retention of up to 30 days and separately approved retention controls. [OpenAI API data controls](https://developers.openai.com/api/docs/guides/your-data).
- Evidence about AI and learning is mixed, so neither "AI always harms learning" nor "AI always teaches" is justified. A randomized developer study found lower immediate mastery with AI assistance, with better outcomes among participants who used AI to build comprehension; its task was learning a new Python library, not Unlock's workflow. [Anthropic original study](https://www.anthropic.com/research/AI-assistance-coding-skills). A controlled experiment with 69 novice learners aged 10–17 found improved code-authoring performance with Codex and no significant drop on later manual modification tasks; this population also differs from junior employees. [Kazemitabaar et al., original paper](https://arxiv.org/abs/2302.07427). These studies support measuring independent transfer rather than assuming either benefit or harm.

## Product recommendations inferred from the sources

1. **Use an explicit "Help me with this code" action.** Capture only the active file's selected function or bounded lines, language, URI/path label, document version/hash, nearby diagnostics, and the learner's stated question. Preview the exact excerpt before use; exclude `.env`, credentials, generated files, and unrelated files. Never silently index the whole workspace. Read-on-demand is possible through the editor API; the minimization and exclusion policy is our design choice.
2. **Mentor handoff should be reviewed content, not a free-form live feed in P0.** A mentor can author a versioned snippet/case with skill tag, scenario, expected invariant, test, approved hint ladder, and provenance. A junior opens it as a read-only comparison or untitled document and applies it only by an explicit edit. A real mentor-to-junior delivery service would require identity, approval, privacy and tenancy design beyond current P0.
3. **Route risk from authored delivery facts; use current code only for context.** Blast radius, production access, customer data, rollback, ownership and reviewer availability cannot be reliably inferred from a selected function or diagnostic. A senior/task owner should declare the delivery boundary; missing facts yield "needs review" rather than a confident low-risk route. Learning value is relative to the learner's target sub-skill and eligible evidence, so the same task can be valuable for one junior and routine for another. These are product rules, not VS Code capabilities.
4. **Choose sub-skills from a small reviewed taxonomy.** The mentor tags tasks and snippets; the extension tracks separate evidence for contract interpretation, discriminating test design, and patch judgment. A file name or LLM guess can suggest a tag but must not silently redefine the skill being assessed. Existing structured answers and G1–G3 evidence remain the source of level changes.
5. **Generate contextual help by selecting a reviewed hint, then localizing it.** Match the current code to an authored case/task ID and skill tag, show the maximum allowed L0–L4 hint, and refer to the actual symbol, diagnostic or selected line only where the match is valid. If no reviewed match exists, offer a non-scored question prompt or a learner-previewed mentor request. Do not reveal a reference fix before first prediction or turn model text into an answer key.
6. **Treat an LLM as an optional later adapter.** It may suggest a sub-skill tag, draft a code-specific question, or rephrase an approved hint using a user-previewed excerpt. Require a strict output schema, enum-bound skill/hint IDs, source references, no code execution or autonomous edits, and review/validation before display. Keep task risk, patch truth, gate scoring, exposure, and level transitions deterministic and auditable. The P0 offline case pack already demonstrates the pedagogical loop without enterprise code export or an API dependency.

## Implication for P0 and the next release

For the five-ticket implementation, the bounded selection command, reviewed local lesson import, and honest no-match fallback can be added without changing the G1–G3 grader. Real editor context is local and unscored; only reviewed synthetic cases earn P0 gates. Authenticated mentor publishing and an LLM adapter require a later code-sharing and review design.
